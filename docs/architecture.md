# アーキテクチャ

## レイヤ構成

```mermaid
graph TD
    UI[UI層<br/>Bubble Tea (list / todo / search / help)]
    APP[アプリケーション層<br/>ユースケース(作成/一覧/検索/削除/完了切替)]
    STORE[ストレージ層<br/>Markdownファイル読み書き(メモ/todo)]
    INDEX[索引層<br/>SQLite / FTS5]
    EDITOR[外部エディタ起動<br/>$EDITOR]

    UI --> APP
    APP --> STORE
    APP --> INDEX
    APP --> EDITOR
    STORE -. 差分をインデックス化 .-> INDEX
```

依存の向きは常に `UI → アプリケーション → ストレージ/索引`。UI層はファイルパスの組み立てやSQLクエリを直接扱わない。逆にストレージ層・索引層はBubble Teaの型を知らない。

## 各層の責務

### UI層(`internal/ui` 想定)
- Bubble Teaの `Model` / `Update` / `View` によるTUI描画
- キー入力のハンドリング、画面遷移(スプラッシュ→メイン画面、メイン画面⇄ヘルプ/削除確認、メイン画面内の検索/タグ/メモ一覧/todoリストパネル間のフォーカス移動)
- 入力(検索クエリ・タグ選択・todoの完了切替)をアプリケーション層に渡し、結果を描画するだけ。ビジネスロジックは持たない

### アプリケーション層(`internal/app` 想定)
- 「新規作成」「一覧取得」「検索」「タグ絞り込み」「削除」「todo完了切替」といったユースケース単位の関数を提供(メモ・todoの双方)
- ストレージ層と索引層を協調させる(例: メモ/todo保存後に索引更新をトリガーする)
- `$EDITOR` の起動もここが担当し、UI層は起動要求を出すだけ

### ストレージ層(`internal/storage` 想定)
- メモ本体・todo本体(いずれもMarkdown + frontmatter)の読み書き
- ファイル一覧の列挙、ファイル名生成、frontmatterのパース/シリアライズ
- 正(source of truth)はここが持つファイル群

### 索引層(`internal/index` 想定)
- SQLite(FTS5)への書き込み・検索クエリ実行。todoはメタデータキャッシュのみ持ち、FTS5索引の対象外とする
- 起動時の再インデックス(mtime突き合わせ)
- 索引はあくまでキャッシュであり、破損・削除されてもストレージ層から再構築可能であること

## 起動時フロー

1. 設定ファイル(`~/.config/noto/config.toml`)を読み込む(なければデフォルト値)
2. 索引DBを開く(なければ作成)
3. ストレージ層のファイル一覧とmtimeを索引と突き合わせ、差分のみ再インデックス
4. UI層を起動し、索引層経由で一覧を初期表示

## 検索の流れ

1. UI層が検索欄の入力をデバウンスしてアプリケーション層に渡す
2. アプリケーション層が索引層(FTS5)にクエリを発行(タグ条件があればANDで結合)
3. 結果(ID・タイトル・スニペット・タグ・更新日時)をUI層に返し、一覧を再描画

詳細なファイル形式・DBスキーマは [data-model.md](data-model.md) を参照。
